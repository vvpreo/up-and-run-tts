# Исследование: локальный TTS для озвучки потокового ответа LLM

Дата исследования: 30 сентября 2026 года. Проведено в сессии проекта
`gigam-serving` (`up-and-run-stt`), результаты перенесены сюда как отправная
точка для проекта `up-and-run-tts`.

## Задача

Нужен простой, но вменяемый локальный способ озвучивать то, что произносит
большая языковая модель. Критическое требование — работа с потоковым текстом:
LLM ещё пишет ответ, а озвучка уже идёт. Целевой язык — русский (это допущение
исследования, пользователь его не оспаривал). Локальное распознавание речи уже
есть — сервис `up-and-run-stt`.

Доступное железо:

- Development Box: GTX 1050 Ti 4 ГБ (занята распознаванием), CPU;
- DGX Spark: aarch64, 121 ГБ unified memory — общий ресурс, использовать только
  по явному указанию пользователя.

## Насколько этому можно доверять

- Собственных замеров не было. Все скорости и задержки — цифры авторов моделей
  или сообщества.
- Ни один Docker-образ и ни одна модель в ходе исследования не запускались.
- Замеров на GTX 1050 Ti нет ни для одной модели; на DGX Spark чужие замеры
  есть только для Qwen3-TTS и VibeVoice-Realtime.
- Независимого сравнения качества русского за 2026 год не найдено; оценки «из 5»
  в отчёте — субъективный обзор одной компании (Raft на Habr).
- Скорость Silero на CPU: авторы заявляют 36× реального времени на одном
  потоке, сторонний замер дал около 5×. Расхождение не снято.

Полный список пробелов — в разделе «Чего это исследование не знает» отчёта.

## Главные выводы

1. Для русского реалистичная схема — нарезка текста LLM по клаузам и
   предложениям перед любой моделью. Нормализация чисел и расстановка ударений
   требуют контекста хотя бы клаузы, поэтому токенный ввод с ними конфликтует.
2. Ни один русскоязычный CPU-движок не принимает текст по токенам.
3. Нативный потоковый ввод текста с официальным русским открыт в коде только у
   Fun-CosyVoice 3 и MOSS-TTS-Realtime. Обе требуют GPU класса Spark, на Spark
   их никто не запускал, по русскому у MOSS нет отзывов, у CosyVoice 3 ударения
   ненадёжны.
4. GTX 1050 Ti для LLM-подобных TTS следует считать непригодной.
5. Числа, даты и сокращения хорошо не читает ни одна модель — нужен отдельный
   нормализатор.

## Что обсудили после отчёта

**Отдельный проект.** TTS решено не встраивать в `up-and-run-stt`: разное
железо, разные зависимости и релизы, некоммерческие лицензии лучших русских
голосов Silero. Склейка «речь → LLM → речь» живёт в приложении, которое ведёт
диалог, а не в STT или TTS.

**Готовые образы** (не проверялись):

- Spark: образы Qwen3-TTS с OpenAI-совместимым API, выложенные на форуме
  NVIDIA специально под DGX Spark (ссылка — в отчёте и в
  `notes/gpu_native_text_streaming.md`);
- CPU: для Silero официального образа нет, есть обёртки сообщества
  (`ndrco/silero_openai_tts`);
- Piper: встроенный HTTP-сервер и Wyoming-сервер, русский заметно слабее;
- Chatterbox: `devnen/Chatterbox-TTS-Server`, на 1050 Ti и Spark не проверялся.

**Почему Qwen3-TTS, хотя ему нужен полный текст.** Полный текст нужен для
одного запроса, а запросом служит очередная клауза, а не весь ответ LLM.
Первый звук появляется через 280–400 мс после отправки куска (чужой замер на
Spark). Цена — возможные швы интонации на стыках. Он выбран вторым шагом,
потому что единственный подтверждённо работает на Spark, имеет готовые образы
и лицензию Apache-2.0.

**Управление голосом.** Пользователю это интересно.

| Решение | Возможности |
|---|---|
| Silero `v5_*_ru` | 5 готовых голосов; SSML: темп, высота, паузы. Клонирования и эмоций нет |
| Silero `v5_cis_base` | Десятки готовых русскоязычных голосов, остальное то же |
| Piper | 4 готовых голоса, темп |
| Qwen3-TTS | Готовые голоса, клонирование по образцу, «дизайн» голоса по текстовому описанию |
| F5-TTS RU, Chatterbox, CosyVoice 3 | Клонирование по короткой записи |

Настоящее управление голосом есть только у GPU-моделей, то есть на Spark.

## Предложенный план

1. Silero на CPU Development Box: замерить скорость синтеза клаузы (1–2 с) и
   предложения (5 с), оценить качество на слух.
2. Параллельно — готовый образ Qwen3-TTS на Spark. Требует явного указания
   пользователя использовать Spark.
3. Вокруг выбранного движка — своя тонкая обвязка: фильтр разметки, нарезчик
   по клаузам, нормализация чисел, выдача PCM по WebSocket с отменой при
   перебивании.

## Открытые решения пользователя

- Будет ли озвучка использоваться коммерчески. От этого зависит ветка Silero:
  `v5_5_ru` (некоммерческая, ударения встроены) или `v5_cis_base` +
  `silero-stress` (обе MIT). У веток разный формат входа.
- Нужен ли именно токенный ввод текста (тогда пробовать MOSS-TTS-Realtime и
  Fun-CosyVoice 3) или достаточно нарезки по клаузам.
- Насколько важно клонирование или дизайн голоса — это сдвигает выбор в
  сторону Spark.
